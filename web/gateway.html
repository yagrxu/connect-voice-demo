Voice Gateway · IoT 设备接入

一个注册的 IoT 设备，
如何鉴权接入语音网关。

这条线把语音能力抽象成一个独立的 voice gateway：真实的 IoT 设备（EC2 上常驻的 speaker-001 进程）先向 IoT Core 拿一张短期票，再用长连接接入网关；网关验票通过后才发起 Connect 语音会话。本页是观测台——它按同一个配对码连上网关，展示设备与网关之间发生的每一步，并作为设备的“麦克风/扬声器”承载真实音频。

注：本页演示的是方案 A（Connect）的设备接入。因为 Connect 走 WebRTC，媒体必须由浏览器承载，才有这套信令/媒体分离的结构。方案 B（Transcribe）/ 方案 C（Nova Sonic）的传输本身就是一条 WebSocket，设备可带票直连推 PCM、无需媒体分离与观测网页，结构更简单——本演示以文档说明，未单独实现（见 架构页）。

信令过程（设备 ↔ 网关）

配对码 speaker-001 设备 观测连接
  1. 1观测台连上网关（role=observer，无需设备票）
  2. 2设备上线：向 IoT Core 拿票后长连接接入
  3. 3网关验票（本地验证，0 次回调 IoT Core）
  4. 4设备请求会话 → 网关 StartWebRTCContact
  5. 5网关把 Chime 加入信息只推给本观测台
  6. 6观测台用麦克风建立媒体流，直连 Connect

设备与网页是两个独立进程，只靠配对码在网关处会合。设备不碰音频，网页不碰鉴权——这就是信令/媒体分离。

演示顺序：先“连接网关（观测）”，等设备上线并起会话后，“加入音频”按钮亮起，点击即可用麦克风与 AI 对话。允许麦克风权限，建议 Chrome / Edge / Firefox。
